# Red-team pass, 2026-11-04 (second pass)

Run with the owner's consent (2026-11-04, "start the work" after approving the plan), on this
repository only, locally, with fake keys. Procedure: `skills/red-team`. Previous pass:
`red-team-2026-11-02.md`.

**Fresh eyes: not met.** This pass was run in the same session that built most of the features it
tests (issues A-D, retest bugs 1-4). The rules ask for a separate agent; the owner did not ask for
one, so the findings below may share the builder's blind spots. A pass by another agent or person
is recommended before v1.0.

## Scope

1. The open findings of the first pass, re-run: RT-1, RT-2, RT-3 (forged or edited approvals,
   state snapshot).
2. Threats the first pass listed but did not test: T1.5 (writing into another project, owner
   decision P-A10-12), T5.4 (unpinned actions, no token permissions, P-A10-14), T4.3 (images from
   other sites).
3. Trust boundaries added since then (step 2 of the procedure):
   - `.agents/task-updates.jsonl`, written by any local program (issue B);
   - the MCP server and skills the app installs in its data folder (retest bug 2);
   - `ui-state.json`, the app's drafts on disk (issue B, retest bug 4);
   - `export_markdown`, a save dialog opened in Rust with a file name from the web view
     (retest bug 4);
   - `approval_withdrawn`, a new person-only event (issue D).
