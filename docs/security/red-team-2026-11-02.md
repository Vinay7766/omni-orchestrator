# Red-team report, 2026-11-02 (dry run)

Scope: a bounded dry run of the security pass (task A10), approved by the owner.
Procedure: `skills/red-team/SKILL.md`. Source of threats: `docs/threat-model.md`
(version of 2026-11-02, after the second adversarial review).

Who ran it: a separate agent session that did not build the features under test
(rule 5). It runs on the same kind of model as the builder, so shared blind spots
are possible; a person or a different tool should repeat the pass before release.

Rules of engagement kept: only local code; no network requests; fake keys only
(assembled at run time, never real); no IDE or other program started (the
launcher's spawn step is replaced by a recorder); files written only to the
system temporary folder and to the test files and this report. No source file
other than tests was changed and nothing was fixed. This is a dry run, so the
open findings are **not** recorded in project memory (skill step 4 says to do so
in a real pass).

## Summary

- **Threats tested:** 10 rows of the threat model (T1.1, T1.6, T2.1, T2.2,
  T2.5, T3.3, T3.4, T4.1, T4.2, T6.2), through 11 abuse cases (RT-1 to RT-11)
  in 19 tests.
- **Controls that held:** 4 abuse cases. RT-4 (no human event or approval
  through MCP), RT-7 (untrusted text renders as text), RT-8 (`javascript:`
  links neutralised, by React), RT-10 (`endpoint_base`). Plus three control
  tests: the phase engine refuses an agent's approval, a key in an event payload
  is redacted, a relative `..` launch path is refused.
- **Findings:** 7 found. Open: 4 (High: RT-1, RT-2, RT-3; Low: RT-9). Fixed
  2026-11-03: RT-11 (Medium), RT-5 and RT-6 (Medium).
- **The project is not shown to be secure** by this pass: it is a bounded dry run
  of 10 of the threat model's 36 rows.

### Notes for the blue team

- RT-3 is the cheapest of the three gate findings to reach: no log line is
  needed. The threat model already says C17 does not cover the snapshot; the
  test shows `PhaseEngine.start` trusts any schema-valid `state.json`.
- RT-1 and RT-2 need C17 (signed approvals, hash chain) and, per T2.6, signing
  outside the web view.
- RT-5 and RT-6: `actor.tool` and `actor.model` go around `redactJson` in
  `MemoryStore.appendEvent`; the payload is redacted, the actor is not.
  Fixed 2026-11-03: the actor is now redacted in the same call
  (`docs/design-notes/2026-11-03-rt5-rt6-actor-redaction.md`).
- RT-11: the test asserts either a refusal or an absolute path that cannot be
  read as an option; either fix turns it green.
- RT-9: the threat model's own suggestion (only `https:` source links) turns it
  green.

### Found by the red team (step 2), not tested

- An MCP client may call itself `omni-desktop` (the desktop app's own tool
  name); the event keeps `kind: "agent"` (RT-4), but any view that shows only
  the tool name would present the agent's work as the app's. Not tested: needs a
  check of every place the UI shows `actor.tool`.
- `data:` and `file:` source links (RT-9) were not in the threat model's T4.2
  row, which names only `javascript:`.

- **Out of the bounded scope (testable locally, left for the full pass):**
  T1.2, T1.3, T1.4, T1.5, T2.3 (existing `phases.test.ts` covers it; not

  T6.4, T6.5.
- **Would need a launched program:** T6.1 (batch-file argument escaping)
  needs a real `.cmd` launcher to start; the rules for this run forbid starting
  programs. A full pass can use a harmless `.cmd` written to a temporary folder
  that only records its arguments.
- **Not built yet:** T1.7 (transcripts), and T2.6 depends on C17.
- **Needs a real third-party service, a release artifact or the owner's
  decision:** T5.3 (covered by the existing embedded-content test), T5.6
  (no signed release exists), T7.1 (needs network logging of the real app).
- **Proposed accepted risks, nothing to test until the owner decides:** T3.5,
  T3.6, T4.4, T7.1.
- **Real-app rendering:** RT-7, RT-8 and RT-9 ran in jsdom, not in the Tauri
  web view, so the CSP (`script-src 'self'`) and WebView2's handling of `data:`
  and `file:` links were not exercised.

## How to re-run

```powershell
# from packages/core
npx vitest run src/memory/red-team.test.ts
# from packages/mcp-server
npx vitest run src/red-team.test.ts
# from the repository root (app tests)
npx vitest run src/components/skills/red-team.test.tsx
# from the repository root, PowerShell (quote the separator, or PowerShell drops it)
.\scripts\cargo-dev.ps1 test --test red_team_tests
.\scripts\cargo-dev.ps1 test --test red_team_tests '--' --ignored
```

A test marked `it.fails` or `#[ignore = "RT-n: ..."]` is an open finding. When a
fix lands, `it.fails` starts reporting a failure (the attack no longer works):
remove the marker then, and remove `#[ignore]` from the Rust test.
