## What C17 does

- **Chained log.** Every new line of `events.jsonl` carries `prev`, the SHA-256 of the line before
  it. An edited, inserted or removed earlier line breaks the chain and is reported.
- **Signed person decisions.** Approve, request changes, skip and withdraw are signed with an
  Ed25519 key kept in the system credential store. Rust signs only after the person confirms in
  a native dialog that the web view cannot draw or click, and builds the dialog's text from the
  signed message itself (T2.6). The signature names the project and the event's id, so it cannot
  be copied into another project or replayed.
- **Verified everywhere.** The app, the MCP server and the VS Code extension check signatures
  against the app's public key in `trust.json` (in the app's data folder, outside every project).
  A decision counts only when its signature verifies. A copied event id counts once.
- **Older projects.** Unsigned decisions written before the log was chained still count; the
  project page notes them as not signed.
- **The extension** cannot sign. Approve, request changes and skip now send the person to the
  desktop app instead of recording a decision that would not count. Running an optional phase
  still works there. This removes a feature the extension had; the owner may want an extension
  key later (see open items).
- **Two confirmations in the app.** The app's own "Yes, approve" button is followed by the native
  dialog. The second one is the protection; the first could be removed in the UI/UX work (H8).

## Still open, and limits

- **RT-16 (Medium).** To close it, either send the commit hash for each of: `actions/checkout@v4`,
  `actions/setup-node@v4`, `dtolnay/rust-toolchain@stable`, `swatinem/rust-cache@v2`,
  `tauri-apps/tauri-action@v0` (as you trust them today), or run a pinning tool such as `pinact`
  locally and push the result. The test then passes and the marker comes off.
- **Truncation.** Removing the last lines of the log (for example a withdrawal) leaves no broken
  chain. Fix idea: the app keeps the hash of each project's last event it saw, in its data folder,
  and warns when the log no longer contains it.
- **Whole-log rewrite.** A program that removes every signature and chain link makes a project
  look older than signing; its decisions then count with only the grey note. The same fix idea
  (the app remembers that the project was chained) would close it.
- **Same-user malware** can change `trust.json` between app starts or read the credential store
  (T3.6, accepted). The app restores `trust.json` at start and before signing, and warns.
- **Extension status bar** shows events live before they are checked (display only; the gates
  refuse unsigned decisions).
- Carried over, not re-tested: T1.2, T1.3, T1.4, T2.4 (now narrower: the extension records no
  decision), T3.2, T5.1, T5.2, T5.5, T6.1 (needs Windows), T6.3, T6.4.
