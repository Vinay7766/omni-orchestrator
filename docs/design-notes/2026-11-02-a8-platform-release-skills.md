## A8: platform and release skills (2026-11-02)

Problem: the coverage report shows no skill for native mobile apps, desktop packaging and signing, or app-store release, and the cloud domain only knows GCP. Fill these from reputable sources, or say plainly why not.
Constraints: the app ships only each skill's `SKILL.md` (build.rs embeds it; reference files and scripts never reach the person), so a skill whose substance lives in other files is not useful bundled (A5 rule). Every bundled source needs a redistributable license and its text in THIRD_PARTY_LICENSES.md. Third-party skills are instructions agents follow: read in full and scanned for harmful content. Uncovered domains must match `pendingGaps` exactly (test).
Searched: official vendor repositories first (apple: none; android/skills; aws/agent-toolkit-for-aws; microsoft/skills; Kotlin/kotlin-agent-skills), then community lists (twostraws/Swift-Agent-Skills). No Tauri, Electron or fastlane skill repository exists.
Chosen (owner approved the three open choices on 2026-11-02):
- mobile-native: `swiftui-expert-skill` (Antoine van der Lee, MIT) for iOS and macOS, chosen over `swiftui-pro` (Paul Hudson, MIT) because its SKILL.md carries the rules and checklist itself, while swiftui-pro is mostly a list of reference files; `android-cli` (Google, Apache-2.0), a single self-contained file covering project creation, build, run, devices, journeys and docs lookup.
- app-distribution: `asc-release-flow` and `asc-submission-health` (Rudrank Riyam, MIT). They hand off only to each other, require a dry run before `--confirm`, and stop at a failing check. They drive the unofficial `asc` CLI (MIT, 8.2k stars), which holds the person's App Store Connect API key; this is stated in each skill's source section. Google Play: no vetted skill yet (play-policy-insights depends on its Python scripts, including a store scraper).
- cloud: `aws-deployment` (AWS, Apache-2.0), self-contained. Azure: Microsoft's official `azure-deploy` refuses to run without `azure-prepare` and `azure-validate` (about 200 files together), so it is not bundled; recorded in the domain's note so it can be added later. The domain stays a category, not a provider list.
- desktop-apps: no reputable skill exists. A project skill `desktop-release` is written in a second slice from official docs only (Tauri, Apple notarization, Microsoft code signing).
Rejected: swiftui-pro (substance in references), azure-deploy (chain of three), play-policy-insights (scripts), android testing-setup (narrow; the general Android workflow is android-cli), new-silvermoon / krutikJain Android packs (community, android/skills is official).
Shape: each bundled SKILL.md is unmodified plus an appended "Source and license" section (commit pinned, files not bundled, tools and credentials it needs). Domains gain an optional `note` (why a part of the domain has no vetted skill), shown in the coverage report.
Placement: app catalog (`skills/`) and the developer's skills folder (`~/.claude/skills`, new folders only).
Generalisation check: the cloud row lists providers only as skills that exist; nothing in code names AWS, Azure, Apple or Google.
Edge cases tested: a domain with a note renders it; a domain without a note renders unchanged; uncovered domains still match pendingGaps after the removals.
